## 结果 B：与 P1 二进制的同机交替 A/B（回归归因）

criterion 单次 medians（threads=8 组，两侧 target 目录均在 `/home` 分区 →
**输出 871 MB SQL 落盘的文件系统一致**，消除 FS 混杂因子）：

| 对 | 顺序 | P1 median | P2 median | P2−P1 |
|---|---|---|---|---|
| A1 | p1→p2 | 5.7056 s | 5.7221 s | +0.29% |
| A2 | p1→p2 | 5.1434 s | 5.7200 s | +11.21% |
| B1 | p2→p1 | 5.3967 s | 5.6559 s | +4.80% |
| B2 | p2→p1 | 5.6696 s | 5.8055 s | +2.40% |
| B3 | p2→p1 | 5.8618 s | 5.7830 s | −1.34% |

- P1 五中位均值 **5.5554 s**（95.20 MiB/s，散布 ±6.5%），P2 五中位均值
  **5.7373 s**（92.18 MiB/s，散布 ±1.3%）→ 代码增量估计 **+3.3% 耗时**
  （= −3.2% 吞吐），配对 t≈1.6（df=4，p≈0.19），95% CI ≈ **[−2.4%, +9.0%]**
  → **跨 0，不能判定 >5% 回归，也不能判定无回归**。
- 为压噪声再做 **CLI 级 10 对交替**（同一对 bench-profile 二进制、同参数、
  交替顺序，criterion 只是这层的采样壳子）：第 1 轮双侧都异常快
  （1733/2658 ms，与其余轮次差 3× 且 `run.out` 已被覆盖无法复核）→ **剔除伪影**，
  取 2–10 轮：P1 中位 5737 ms、P2 中位 5840 ms，**配对平均差 +38 ms = +0.66%**，
  95% CI ≈ **[−3.8%, +5.1%]**（p≫0.5）→ 与「未解析出」一致。

### 归因：原始 −14.9% = 环境 −8.3% + 代码 −3.2%（余下为噪声/壳层差异）

**P1 二进制今天的最好成绩 5.1434 s / 101.92–103.76 MiB/s 能基本复现 p1.md
的 5.0927 s / 103.85 MiB/s**，说明机器没坏；但 P1 今天的**均值只有 95.20
MiB/s（−8.3%）**，且五轮散布 5.14–5.86 s。也就是说：**基线是在一个更“干净”的
时间窗里采到的，今天任何一次与 P1 数字的直接对比都会先背上 8% 的环境债**。
残余的 +3.2%（criterion 口径）无法与噪声区分，故：

- 不触发「STOP 待裁决」（无 >5% 的代码回归证据）；
- 但**也不宣布 P2 无回归**——列为 finding，附下方后续动作。

## 已知测量陷阱（本轮踩过，钉在文档里防止复发）

1. **并发即污染**：本轮曾出现 `10.649 s / 49.66 MiB/s`（两个 `cargo bench` 同时
   跑）与 `6.8263 s / 77.47 MiB/s`（bench 与 `cargo build --release` 重叠），
   两个读数**作废不入表**。规则：跑基线时机器上不得有任何其他 CPU 活计。
2. **criterion 的输出盘由 target 目录决定**：`CARGO_TARGET_TMPDIR` 随
   `CARGO_TARGET_DIR` 走，跨 target 目录比较 = 跨文件系统比较（871 MB/次写盘
   是主要成本之一）。本轮 A/B 两侧都固定在 `/home`。
3. **powersave + 混合大小核**：调度落 P 核还是 E 核足以造成 ±10% 摆动，
   这是 P1 侧散布 6.5% 的最合理解释（未做 `taskset`/governor 钉核，属
   P3/P4 的测量工装改进项，已挂账）。

## 后续动作（挂账，非收尾阻塞）

- 若要**判定** P2 那 −3.2% 是否真有其事：需要 `governor=performance` +

  P2 未触碰该路径。
