# my2sql-rs P1 实施计划（解码层 + file 模式 + to-sql + 差分基建）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可运行的 `my2sql-rs to-sql`：离线解析本地 binlog（row 格式），输出与 Go 版行为等价的正向 SQL，并建立可重复的差分测试基建。

**Architecture:** 单 bin crate；`binlog/` 自研纯函数解码层（event→table_map→rows→value）；`pipeline/` 用 crossbeam-channel 串起 filter→编号分发→N worker→reorder→writer；`metadata/` 连库取表结构并可导出/导入 JSON schema 文件；`sqlopen/` 做值编码与 DML 拼装。

**Tech Stack:** Rust 2021、clap 4、crossbeam-channel、mysql（同步驱动）、mysql_common（仅 LNE 原语）、crc32fast、simdutf8、serde_json、criterion、cargo-fuzz（P4 前仅挂账）。

**Spec:** `docs/superpowers/specs/2026-09-20-my2sql-rust-design.md`（本计划实现其 §2-§6 的 P1 子集；§9 P2-P4 另出计划）

## Global Constraints

- 支持服务端：MySQL **5.6** / 5.7 / 8.0 / 8.4（Task 17 兼容矩阵逐版本验收）；binlog 必须 `binlog_format=row`；P1 仅承诺 `binlog_row_image=full`；5.6 statement 默认格式需在错误信息中给出显式指引
- 不引入 tokio/async-std；仅 std::thread + crossbeam-channel
- 解码全链路 `&[u8]`/`Vec<u8>` 优先；任何 `String::from_utf8_lossy` 出现在值路径即为缺陷
- datetime/time/timestamp 列值不得实例化为时间类型；chrono 只允许用于 `--start/stop-datetime` 参数解析与注释时间格式化
- 依赖白名单：clap, crossbeam-channel, mysql, mysql_common, crc32fast, simdutf8, serde, serde_json, thiserror, chrono(cli-only), tracing, tracing-subscriber, criterion(dev), proptest(dev)
- 每个任务结束：`cargo test` 全绿 + `cargo clippy -- -D warnings` 干净 + git commit + 更新 `docs/HANDOVER.md`（交接文档：任务细节、决策、遗留项、当前进度；每个任务完成节点统一更新）
- 范围豁免：spec §4.6 的"extra_info 注释携带 ENUM/SET 映射名"推迟至 P2 完善，P1 只输出序号
- 行为参考锚点（只对照不抄代码）：`reference/my2sql-go/base/sqlgen.go`、`reference/my2sql-go/vendor/github.com/go-mysql-org/go-mysql/replication/row_event.go`
